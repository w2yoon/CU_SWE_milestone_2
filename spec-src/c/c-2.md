# Component C — features built on messages — stage C.2 of C.1–C.5 (files)

Build ONLY this stage now. Earlier stages must already pass. Check: `bash /spec/c/checks/check_c_2.sh`.

**Functions used from earlier stages:** `auth_user`, `message_obj`, `create_message`, `channel_member`

**Functions added in this stage:** `parse_multipart(handler)`, `file_obj(row)`, `save_file(...)`, `attach_files(conn,message_id,file_ids,user)`

`FileObj = {id, uploader_id, filename, content_type, size, created_at}`. Store bytes on disk under `/app/data/files/<id>` (or as a BLOB) so every node can serve them. Parse multipart with the standard library (`email.parser.BytesParser` on `Content-Type` header + body); do not use the removed `cgi` module.

| ID | Request | Required result |
|---|---|---|
| C2.1 | `POST /api/files` multipart with a `file` part (`hello.txt`, `text/plain`) | `201 {file}` with all FileObj fields, `size` = byte length, `filename` and `content_type` echoed, `uploader_id` = caller |
| C2.2 | `GET /api/files/{id}` (on another node) | `200 {file}` same object |
| C2.3 | `GET /api/files/{unknown}` | `404` |
| C2.4 | `GET /api/files/{id}/download` | `200`, body = the exact bytes, `Content-Type` = stored type, `Content-Disposition: attachment; filename="hello.txt"` |
| C2.5 | upload larger than 10 MiB (10485760 bytes) | `413` (check `Content-Length` before reading the body) |
| C2.6 | no `file` part / no token | `400` / `401` |
| C2.7 | `POST /api/channels/{id}/messages {"body":"see file","file_ids":[id]}` by the uploader | `201`; `message.files == [FileObj]`, also in history |
| C2.8 | attach the same file again | `400` (already attached) |
| C2.9 | attach a file uploaded by someone else / an unknown file id / `file_ids` not a list | `400` |
