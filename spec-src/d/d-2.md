# Component D — cluster robustness — stage D.2 of D.1–D.4 (WebSocket across a killed node)

Build ONLY this stage now. Earlier stages must already pass. Check: `bash /spec/d/checks/check_d_2.sh`.

**Functions used from earlier stages:** `ws_handler` (subscribe/resume/poll), `emit_event`, supervisor restart loop

**Functions added in this stage:** none required if the earlier design is followed; fix whatever breaks

Each node must be stateless: `event_id` comes only from `channel_seq` inside a `BEGIN IMMEDIATE` transaction; `subscribe`/`resume` read only from `events`; nothing about other nodes' sockets is kept in memory. A WebSocket handler thread must exit cleanly when its socket dies (catch `OSError`/`BrokenPipeError`), and HTTP requests must never wait on a WebSocket.

| ID | Behaviour | Required result |
|---|---|---|
| D2.1 | subscribers on 8000 and 8002; `SIGKILL` node 8001 | both sockets stay open |
| D2.2 | while 8001 is down, post on 8000 and 8002 | `201` each; both subscribers receive both `message.created` frames with dense ids `head+1, head+2` |
| D2.3 | open a new socket on 8002 and `resume` from `head` | replays exactly those 2 events, then `resumed` |
| D2.4 | `SIGKILL` node 8000 while its subscriber is connected; post 2 messages on 8002; reconnect to 8001 (back up) and `resume` from the last id seen | the 2 missed events in order, then `resumed` |
| D2.5 | after node 8001 is back, post on 8001 | the subscriber on 8002 receives it live with the next dense id |
| D2.6 | `subscribe` on every node | the same `head_event_id` on all three |
