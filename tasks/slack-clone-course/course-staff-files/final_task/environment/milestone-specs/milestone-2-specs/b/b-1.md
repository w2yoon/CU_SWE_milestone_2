## Conventions (apply to every endpoint below)

- Base `http://127.0.0.1:8000` (nodes `:8000 :8001 :8002` all serve the same data). Routes under `/api/...`, JSON in/out.
- Auth header `Authorization: Bearer <token>`. Missing/invalid token on an authenticated route → `401`.
- Success: `200` read/update, `201` create. Errors: `400` validation, `401` auth, `403` forbidden, `404` unknown id, `409` conflict, `423` archived channel write.
- Responses use one top-level resource key (`user`, `workspace`, `channel`, `message`, `member`, `invitation`, `workspaces`, `members`, `channels`, `messages`, `replies`, `pins`, `results`, ...).
- Check order for every route: **401 (auth) → 404 (unknown id/slug) → 403 (permission) → 400 (body validation)**.
- Timestamps: UTC ISO-8601 with `Z`, e.g. `2026-05-16T08:07:34.123Z`.
- ALL state (users, tokens, workspaces, roles, invitations, channels, messages, event counters) lives in the shared SQLite file, never in process memory: the three nodes are separate processes and any node may be killed and restarted at any moment.

### Channel management

`ChannelObj` = `{id, workspace_id, name, is_private, is_dm, topic, is_archived}` (booleans are real JSON booleans).

| ID | Request | Required result |
|---|---|---|
| B1.1 | `POST /api/workspaces/{slug}/channels {name,is_private?,topic?}` | `201 {channel}`; `topic` defaults to `""`; creator becomes a member |
| B1.2 | duplicate `name` in the same workspace | `409` |
| B1.3 / B1.4 | name > 32 chars, or not kebab-case (`Bad Name`) | `400` |
| B1.5 / B1.6 | `topic` 251 chars / short topic on create | `400` / `201` with topic stored |
| B1.7 | no token | `401` |
| B1.8–B1.10 | `PATCH /api/channels/{id} {topic}` by owner / channel member (250 chars ok) / 251 chars | `200 {channel}` / `200` / `400` |
| B1.11 | PATCH topic by someone who is neither channel member nor workspace owner | `403` |
| B1.12 | PATCH unknown channel | `404` |
| B1.13 | `GET /api/workspaces/{slug}` | `200 {workspace, channels, read_state}` |
| B1.14 / B1.15 | private channel in that list | omitted for non-members, present for members |
| B1.16 | `GET /api/channels/{id}/members` | `200 {members:[UserObj]}`, `UserObj` = `{id, username, display_name, timezone, avatar_url, status_text, status_emoji}` |
| B1.17 / B1.18 | `POST /api/channels/{id}/leave` twice | `200 {channel}` both times (idempotent) |
| B1.19 | after leave | user no longer in channel members |
| B1.20 | `POST /api/channels/{id}/archive` by non-workspace-owner | `403` |
| B1.21 | by workspace owner | `200 {channel}` with `is_archived:true` |
| B1.22 | `POST .../messages` on an archived channel | `423` (all writes: messages, edits, pins, reactions) |
| B1.23 / B1.24 | workspace detail | archived hidden by default; `?include_archived=1` (or `true`) shows it |
| B1.25 / B1.26 | `POST /api/channels/{id}/unarchive` by owner | `200`, `is_archived:false`, writes `201` again |
