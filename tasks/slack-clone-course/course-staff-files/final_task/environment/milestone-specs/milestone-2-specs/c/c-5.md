# Component C — features built on messages — stage C.5 of C.1–C.5 (profiles)

Build ONLY this stage now. Earlier stages must already pass. Check: `bash /spec/c/checks/check_c_5.sh`.

**Functions used from earlier stages:** `auth_user`, `user_obj`, `ws_handler`

**Functions added in this stage:** `patch_profile(user, body)`, `emit_global(type,payload)`; `ws_handler` also forwards global events

`UserObj = {id, username, display_name, timezone, avatar_url, status_text, status_emoji}` (defaults: `display_name` = username, `timezone` = `"UTC"`, others `""`).

| ID | Request | Required result |
|---|---|---|
| C5.1 | `GET /api/users/{id}` | `200 {user}` with every UserObj field |
| C5.2 | unknown id / no token | `404` / `401` |
| C5.3 | `PATCH /api/users/me {display_name,timezone,status_text,status_emoji,avatar_url}` | `200 {user}` with the new values; `GET /api/users/{id}` on another node returns them |
| C5.4 | PATCH with only `{status_text}` | other fields unchanged |
| C5.5 | `timezone:"Mars/Olympus"` (validate with `zoneinfo.ZoneInfo`) | `400` |
| C5.6 | `display_name` empty or > 80 chars; `status_text` > 140; `status_emoji` > 64; `avatar_url` > 512; any non-string value | `400`, nothing saved |
| C5.7 | after a PATCH on node 8000, any open WebSocket on any node (even with no subscription) | receives `{"type":"user.updated","user":UserObj}` within 1 s — no `channel_id`, no `event_id` |

Global events: table `global_events(id INTEGER PRIMARY KEY AUTOINCREMENT, payload)`; each WebSocket remembers the max id at connect time and forwards newer rows in its polling loop.
