### Durable events over WebSocket (dense per-channel sequence, 3 nodes)

Connect `ws://127.0.0.1:<8000|8001|8002>/api/ws?token=<bearer>` (bad token → handshake rejected, never `101`). Frames are JSON text frames. Server frames must be valid unmasked WebSocket frames (length encoding: 7-bit, 16-bit for 126–65535 bytes, 64-bit above).

Client → server: `{"type":"subscribe","channel_id":N}`, `{"type":"resume","channel_id":N,"since_event_id":K}`.
Server → client: `{"type":"subscribed","channel_id":N,"head_event_id":H}` right after subscribe; for `resume`: every event with `event_id > K` in order, then `{"type":"resumed","channel_id":N,"head_event_id":H}`; if `K` is older than the retained tail `{"type":"resume.gap","channel_id":N,"earliest_event_id":E}`.

Durable kinds (each carries `{type, event_id, channel_id, ...}`): `message.created` (top-level), `message.reply`, `message.updated`, `message.deleted`, `reaction.added`, `reaction.removed`, `member.joined`, `member.left`, `channel.updated`, `channel.archived`, `channel.unarchived`.

**Required design (do not deviate):**
1. Table `events(channel_id, event_id, type, payload_json, PRIMARY KEY(channel_id,event_id))` and table `channel_seq(channel_id PRIMARY KEY, last_event_id)`.
2. Every state change that is a durable kind runs in ONE transaction opened with `BEGIN IMMEDIATE`: change data → `last_event_id = last_event_id + 1` → insert event row with that id → commit. Never compute `max(event_id)+1` outside such a transaction. Set `PRAGMA busy_timeout=5000` on every connection.
3. Fan-out across nodes: each WS connection thread polls `events` for its subscribed channels (`event_id > last_sent`, every ≤ 100 ms) and writes new rows to its socket. Do NOT rely on an in-process `WS_CLIENTS` list — it only reaches clients of the same node.
4. `resume` and `subscribe` read only from `events`/`channel_seq`. Retain at least the last 1000 events per channel.
