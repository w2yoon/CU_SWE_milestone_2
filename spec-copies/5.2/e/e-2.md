# Component E — IRC, web UI and message edits — stage E.2 of E.1–E.5 (IRC registration)

Build ONLY this stage now. Earlier stages must already pass. Check: `bash /spec/e/checks/check_e_2.sh`.

**Functions used from earlier stages:** `db()`, token lookup from `auth_user` (move it into a shared module both processes import)

**Functions added in this stage:** `/app/irc.py` (a `socketserver.ThreadingTCPServer` on `0.0.0.0:6667`, `allow_reuse_address = True`), `irc_send(conn, line)`, `handle_registration(...)`; the supervisor starts and restarts it like an HTTP node (see D.1 process layout)

Lines end with `\r\n`; accept `\n` too. Server prefix `:huddle`. Numerics are `:huddle <NNN> <nick or *> ...`.

| ID | Client sends | Required server reply |
|---|---|---|
| E2.1 | `PASS <valid bearer token>`, `NICK alice`, `USER alice 0 * :Alice` | `001`, `002`, `003`, `004`, `005` in that order, then `422` (no MOTD) |
| E2.2 | `PASS badtoken`, `NICK x`, `USER x 0 * :x` (or no `PASS` at all) | `464` (password incorrect), then close |
| E2.3 | `NICK alice` while another registered client holds `alice` | `433 * alice :Nickname is already in use`; the connection stays open, and a later `NICK alice2` + `USER` completes registration (`001`) |
| E2.4 | `PING :abc` | `PONG huddle :abc` |
| E2.5 | `FOOBAR` after registration | `421 <nick> FOOBAR :Unknown command` |
| E2.6 | `QUIT :bye` | the server closes the socket and sends no error numeric |
| E2.7 | `PONG`, `MODE <nick>`, `WHO`, `LIST`, `NAMES`, `TOPIC` | accepted: never `421` |

Nick ownership is in-memory in the gateway (one process); release it when the socket closes.
