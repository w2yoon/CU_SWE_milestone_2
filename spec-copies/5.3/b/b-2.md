### Messages

`MessageObj` = `{id, channel_id, author_id, author(UserObj), body, parent_id, reply_count, created_at, edited_at, files, reactions, mentions}`. `parent_id` is `null` for top-level; `reply_count` counts non-deleted replies; REST message objects do NOT carry `event_id`.

### Cursor pagination (all list endpoints: messages, replies, search, pins)

Every list takes `?limit=N&cursor=<opaque>` and returns top-level `next_cursor` (string while more results exist, `null` on the last page). Cursor is opaque (e.g. base64 of the last-seen sort key), resumes from the same position even if new items arrive, and is valid on every node. `limit` default `50`, max `200`; outside `1..200` or non-integer → `400`. Unparseable/unknown cursor → `400`. No `?page=`/`?offset=`.

| ID | Request | Required result |
|---|---|---|
| B2.5 | `GET /api/channels/{id}/messages?limit=2` after 5 posts | newest-first `[m5,m4]`, `next_cursor` string |
| B2.6 | next page via cursor, on a different node, after a 6th message was posted | `[m3,m2]` (new message does not shift it) |
| B2.7 | last page | `[m1]`, `next_cursor: null` |
| B2.8 | no params | all (≤50) newest-first, `next_cursor: null` |
| B2.9–B2.11 | `limit=0` / `201` / `abc` | `400` |
| B2.12 | `cursor=@@garbage@@` | `400` |
| B2.13 / B2.14 | `limit=200` ok; no token | `200` / `401` |
| B2.16 / B2.17 | `GET /api/messages/{parent_id}/replies?limit=&cursor=` | `200 {replies, next_cursor}` oldest-first, pageable |
| B2.18 | parent after 2 replies | `reply_count == 2` |
