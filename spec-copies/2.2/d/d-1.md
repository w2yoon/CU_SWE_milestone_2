Build ONLY this stage now. Earlier stages must already pass. Check: `bash /spec/d/checks/check_d_1.sh`.

**Functions used from earlier stages:** `supervisor.py` child loop, `db()`, `auth_user`, `create_message`

**Functions added in this stage:** `spawn_redis()` and its restart branch in the supervisor loop; `on_node_start()` cleanup

## Conventions (apply to every endpoint below)

- Base `http://127.0.0.1:8000` (nodes `:8000 :8001 :8002` all serve the same data). Routes under `/api/...`, JSON in/out.
- Auth header `Authorization: Bearer <token>`. Missing/invalid token on an authenticated route → `401`.
- Success: `200` read/update, `201` create. Errors: `400` validation, `401` auth, `403` forbidden, `404` unknown id, `409` conflict, `413` upload too large, `423` archived channel write.
- Responses use one top-level resource key (`user`, `message`, `file`, `group`, `groups`, `reactions`, `channel`, ...).
- Check order for every route: **401 (auth) → 404 (unknown id) → 403 (permission) → 400 (body validation)**.
- Timestamps: UTC ISO-8601 with `Z`, e.g. `2026-05-16T08:07:34.123Z`.
- ALL state lives in the shared SQLite file (or files under `/app/data`), never in process memory: any node may be killed at any moment.


### Process layout (required)

`/app/start.sh` = `exec python3 /app/supervisor.py` (foreground). The supervisor owns these children, each started with `start_new_session=True`, and checks them every ≤ 0.5 s; any child that exits is restarted at once:

- 3 HTTP nodes: `python3 /app/server.py` with `NODE_ID`=0/1/2, `PORT`=8000/8001/8002.
- Redis: `redis-server --bind 127.0.0.1 --port 6379 --save "" --appendonly no` (installed in the image; do not `pip install` anything for it).
- (Component E, when built) the IRC gateway `python3 /app/irc.py` on `0.0.0.0:6667`, as its own process so that killing an HTTP node never stops IRC.

Redis must run, but it is NOT on the delivery path: cross-node fan-out keeps using the shared SQLite `events` table that every WebSocket polls (B.4 / basics). Never block a write on Redis. If you publish to Redis at all, use a socket timeout ≤ 0.2 s and ignore every error.

Restart the cluster only by PID: write the supervisor PID to `/tmp/supervisor.pid`; on SIGTERM the supervisor kills its children (by their saved PIDs) and exits. Never kill by name.

|---|---|---|
| D1.1 | `GET /api/health` on 8000/8001/8002 | `200 {"status":"ok","node_id":0/1/2}` |
